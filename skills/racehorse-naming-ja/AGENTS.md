# AGENTS.md（racehorse-naming-ja 固有）

このスキル固有の編集メモ。全スキル共通の指針は [リポジトリ root の AGENTS.md](../../AGENTS.md) を参照（このファイルが優先）。

- **`SKILL.md` の例には実在の競走馬を使う。** 血統・命名由来などの事実は裏取りしてから書く。
- **`evals/evals.json` で題材にしている馬・馬名・その父母は、`SKILL.md` の例に使わない**（評価への過剰適合回避）。例は実在かつ非evalの馬から選ぶ（例: クロワデュノール／ブラウンラチェット／ウオッカ）。
- **品評ケースを追加・改訂するときは、期待する採点を `target_grade_band` / `target_symbols` / `target_band_shift` / `target_note` で書く**（[下記](#品評ケースのメタデータevalsjson)）。`SKILL.md` の採点表と食い違えば `scripts/lint_skills.py` が落ちるので、採点表を変えたときは既存ケースの記号・帯も合わせて見直す。

## 品評ケースのメタデータ（evals.json）

品評ケース（`"mode": "品評"`）は期待する採点を機械可読な形で持ち、`scripts/lint_skills.py` が SKILL.md の「土台グレード」表と突き合わせて自己矛盾（記号と帯の食い違い）を検出する。

| フィールド | 内容 |
|---|---|
| `target_grade_band` | 期待する総合グレード帯。`S+`/`S`/`A`/`B`/`C`/`不可`。幅を持たせるなら `A〜S` |
| `target_symbols` | 土台3軸の記号 `{"連想": …, "言語一致": …, "背景": …}`。値は `—`/`△`/`○`/`◎`/`◉`、範囲は `○〜◎` |
| `target_band_shift` | 副次パーフェクト昇格 `+1`・制約違反による減格 `-1` などの段数（省略時 0） |
| `target_note` | 自由記述（そのケースの狙い・補足） |

- 検証は「記号から採点表が導く帯が `target_grade_band` に収まるか」。導かれる帯を含んでいれば通る（記号が `B` を導くとき `C〜B` は可）。
- `target_grade_band`・`target_symbols`・`target_note` は品評ケースの必須。固定しないケース（登録可否が主眼・記号が開くなど）は値に `null` を明示する。
- `不可`（Mゲートの確定却下）は採点に進まないので記号を持たない。
- 採点表は SKILL.md から読むため、表を改訂すれば検証もそのまま追随する（表の書式を変えると lint が落ちて突き合わせを促す）。

## 評価の実測（39 ケース）

評価の進め方は [README の評価（eval）](../../README.md#評価eval)。以下はこのスキルで測った値で、README の設計判断の根拠。

- **隔離セッション**: サブエージェント方式との 1 ラン中央値の比較で、API ターン 18→5、Σcache_read 1.19M→0.11M、Σcache_create 70k→40k。
- **regex grader**: 320 grader → llm 246 ＋ regex 59 にして、39 出力で llm 判定と全一致。regex で受けるのは SKILL.md の節名・語（凡例・良い点／気になる点・要確認・総合判定など）。
- **ジャッジ**: Sonnet ジャッジは 320 grader 中 68 本を旧方式の Opus 採点と食い違う FAIL にした（日本語の条件文の読み違いが主因）。Opus ジャッジは旧方式と同じ通過率 0.94。費用はランナー見積で 1 周あたりジャッジ $45 前後・実行 $67 前後。
- **WebSearch のみ許可**: SKILL.md は「一般的なウェブ検索で照合」としており、WebFetch を許可しなくても仕様に反しない。

## JAIRS 文書（登録基準・審査）の扱い

`SKILL.md` の「M. MUST要件」は JAIRS の2文書からの**転記スナップショット**で、これがスキル実行時の唯一の正。**実行時に原典 PDF を取得させる指示は書かない**（毎回の fetch は遅く・不安定で、参照先の可用性にスキルの挙動が依存するため）。

原典の改訂を取り込むのは**スキル改版というメンテナンス作業**であり、以下の手順で行う。

1. 原典を確認する（[実施基準](https://www.jairs.jp/contents/pdf/bameitourokujisshikijyun.pdf)は「最終改正」日付、[審査について](https://www.jairs.jp/contents/pdf/bameitourokusinsa.pdf)は版番号が付かないので記載内容）。
2. 変更があれば `SKILL.md` の該当箇所へ差分を反映し、**転記した版の表記も更新する**（実施基準＝最終改正の日付・規約番号／審査について＝転記時点の日付）。
3. 却下基準・保護期間など判定に効く変更を含む場合は、root の AGENTS.md の方針どおり `evals` で旧版/新版を比較してから確定する。
4. `metadata.version` を上げ、`CHANGELOG.md` に「どの文書のどの版を取り込んだか」を記録する。
